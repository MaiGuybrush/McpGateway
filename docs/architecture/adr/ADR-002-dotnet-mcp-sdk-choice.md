# ADR-002: 選擇 .NET MCP SDK 而非 Java 或其他替代方案

## 狀態
**✅ 已批准**（團隊技能確認完成）

## 背景

在決定採用 MCP 協定後，需選擇實作語言與 SDK。可選方案：

1. **.NET MCP SDK**：官方 C# SDK，搭配 ASP.NET Core Minimal API
2. **Java MCP SDK**：社群維護的 Java 實作（如 icdotorg/mcp-java-sdk）
3. **Python MCP SDK**：若採 Python 實作，與 Pydantic AI 同生態系

## 決策

**✅ 確定採用 .NET MCP SDK + ASP.NET Core**

### 理由（已確認）

1. **團隊技能確認**
   - 團隊內有熟悉 C# 的專職人員
   - Tool Facade 維護責任可明確指派給 .NET 團隊
   - 與現有 Java 系統維護團隊分離，無跨語言維護負擔

2. **基礎設施優勢**
   - Ocelot Gateway 使用 .NET，團隊已有相關經驗
   - 與現有 .NET 服務共享 CI/CD 流程
   - 一致的部署與監控體系

3. **SDK 成熟度** ⚠️ **部分未驗證**
   - .NET SDK 為官方維護，功能最完整
   - 更新頻率高，文件齊全
   - ~~Streamable HTTP 支援完整（經 PoC 驗證）~~
     🔴 **此宣稱無依據（2026-08-02 查核）**：PoC 未產生可編譯的程式碼
     （`ITool` 重複定義 CS0101 等），且 `csproj` 引用的是 `ModelContextProtocol 0.1.0-preview.*`，
     `ModelContextProtocol.AspNetCore`（Streamable HTTP 所需）**根本未被引用**。
     詳見 [ADR-001](ADR-001-use-mcp-protocol.md) 狀態欄查核發現。
     → **待 Sprint 0 SDK spike 驗證後補正。**

4. **效能考量**
   - .NET Runtime 效能優良，適合高併發
   - Memory 與 CPU 效率優於 Java（同場景基準測試）
   - 啟動速度快，適合快速擴縮

5. **生態系整合**
   - 與現有 Ocelot Gateway 同語言，知識共享
   - 可參考 Ocelot 的設計模式與最佳實踐
   - 工具鏈一致（dotnet CLI, Azure DevOps 整合）

### 風險評估（更新）

| 風險 | 機率 | 影響 | 應對措施 | 狀態 |
|-----|------|------|---------|------|
| SDK bug 影響進度 | 低 | 中 | 預留 20% buffer；參與開源社群貢獻修復；必要時 fork SDK | ✅ 可控 |
| .NET 生態系統限制 | 低 | 低 | 在 PoC 階段驗證所有依賴；建立退路（Rollback 計劃） | ✅ 可控 |
| 團隊負荷過重 | 中 | 中 | 確保專職負責人，不兼職；合理排程，避免 burnout | ✅ 可控 |

**已解除風險**（經團隊確認）：
- ❌ 團隊 C# 技能不足 → ✅ 已有專職人員
- ❌ Java 團隊維護困難 → ✅ 責任明確分工
- ❌ 招聘難度 → ⚠️ ~~維護範圍有限（單一服務）~~ → **見下方 ADR-009 修訂**

### 🔄 【ADR-009】維護範圍論述修訂（2026-08-02）

本 ADR 原以「**維護範圍有限（單一服務）**」作為解除招聘難度風險的論據。
[ADR-009](ADR-009-department-gateway-split.md) 拆分為 `McpGateway.Core` + N 個部門專案後，此論述需修正。

**修正後的維護範圍**：

| 元件 | 維護者 | C# 深度需求 | 說明 |
|------|--------|-----------|------|
| `McpGateway.Core` | 平台團隊（專職 C#） | **高** | MCP SDK 整合、認證管線、傳輸層、驗證框架 |
| `McpGateway.{Dept}` | 各部門開發者 | **低** | 僅需寫 `ITool` 類別 + `[Description]` 標註 |

**招聘難度風險仍為已解除，理由改為**：

- 需要深度 C# 能力的範圍**仍然只有一個元件**（Core），且維護者為專職平台團隊
- 部門專案因 [ADR-009 D2 極薄邊界](ADR-009-department-gateway-split.md) 設計，`Program.cs` 僅 3 行，
  部門開發者只需寫工具邏輯與描述文字，**不需要理解 MCP 協定、認證管線或傳輸層**
- 換言之：服務數量從 1 增為 N，但**需要資深 C# 能力的範圍未增加**

⚠️ **新增風險（低）**：Core 成為 N 個部門的共同依賴，其維護者離職的影響面大於單體時期。
**緩解**：Core 需至少 2 名可維護人員（bus factor ≥ 2），且對外介面須有完整規格文件與契約測試。
